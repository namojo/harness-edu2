# 교육 사이트 정보설계

## 이 설계가 해결하려는 문제

harness-edu(1세대)는 7차시 + 확장트랙 3개 + 도구 문서로 커졌다. 콘텐츠가 나빴던 게 아니라, **어디서 시작해 어디서 끝나는지가 안 보였다.** 학습자는 목차를 보고 이탈했다.

harness-edu2는 120분 워크샵 하나를 위한 교재다. 그래서 정보설계의 목표는 "많이 담기"가 아니라 **"120분을 완주시키기"** 다.

## 페이지 맵 (확정)

```
docs/
├── index.html              홈 — 무엇을 배우나 · 120분 흐름 · 실습 3개 진입
├── concept.html            개념 — 하네스 엔지니어링 · 메타스킬 6단계 · 6가지 패턴  (15분)
├── practice/
│   ├── 1-youtube.html      실습 1 — 유튜브 콘텐츠 기획 팀                        (25분)
│   ├── 2-marketing.html    실습 2 — 브랜드 마케팅 전략보고서                     (30분)
│   └── 3-pptx.html         실습 3 — 샘플 형식으로 새 PPT 만들기                  (40분)
├── install/                설치가이드 — harness-edu에서 무손실 이관 (5문서)
└── assets/                 site.css · site.js · 실습 첨부 자산
```

**본문 페이지는 5장이다.** 설치가이드는 사전 준비물이라 학습 동선의 본류가 아니다.

## 페이지를 늘리려는 충동에 대한 판단 기준

새 페이지를 만들고 싶을 때 다음 순서로 자문한다:

1. **이 내용 없이 실습 3개를 완주할 수 있는가?** → 할 수 있으면 만들지 않는다. (1세대에 이미 있고, 링크로 보내면 된다)
2. **기존 5장 중 어딘가의 한 섹션으로 들어가는가?** → 들어가면 섹션으로 넣는다.
3. **둘 다 아니라면** → 사용자에게 페이지 추가를 승인받는다. 조용히 늘리지 않는다.

FAQ·용어집·심화 패턴 2종·트러블슈팅 모음은 전부 1번에서 걸러진다. 트러블슈팅은 각 실습 페이지의 "이럴 때는" 블록에 분산 배치한다 — 별도 페이지로 빼면 실습 중에 아무도 찾아가지 않는다.

**다운로드 페이지도 만들지 않는다.** 같은 이유다. 실습 파일 다운로드는 그것이 필요한 실습 페이지의 "준비물" 블록에 둔다. 학습자가 파일을 찾는 시점은 그 실습을 시작하는 순간이고, 그때 보고 있는 화면이 그 실습 페이지다. 별도 다운로드 페이지는 "어디서 받나"를 한 번 더 찾게 만든다.

단, 홈에는 **한 줄 안내**를 둔다: 실습 파일은 설치가이드의 `git clone` 으로 한 번에 받거나 각 실습 페이지에서 개별로 받을 수 있다는 사실. 사전 준비의 존재를 모르는 학습자가 실습 3에서야 알게 되는 것을 막는다.

## 학습 동선

```
[사전]  홈 → 설치가이드 (필수 1 + 선택 2)
[본수업] 홈 → 개념 15분 → 실습 1 25분 → 실습 2 30분 → 실습 3 40분
                              │              └──── 산출물 ────┐
                              └── 패턴 언어 제공 ──────────────▶ (실습 3 입력)
```

동선 규칙:
- **모든 본문 페이지 하단에 이전/다음 페이저를 둔다.** 학습자가 다음에 뭘 할지 스스로 판단하게 만들지 않는다.
- **개념 페이지는 실습으로 나가는 링크를 각 개념 블록 끝에 둔다.** 개념만 읽고 끝나는 경로를 만들지 않는다.
- **실습 3 페이지 상단에 실습 2 의존성을 명시**하고, 실습 2를 건너뛴 경우의 우회 경로를 함께 둔다.
- 설치가이드에서 본수업으로 돌아오는 링크는 "개념"이 아니라 **"실습 1"** 을 향한다. 설치를 끝낸 사람의 다음 관심은 "돌아가나?"이고, 그건 실습에서 확인된다.

## 한 페이지의 필수 상단 블록

모든 본문 페이지는 상단에 세 줄을 둔다. 없으면 학습자는 자기가 지금 무엇을 하는지 모른다.

| 블록 | 내용 | 예 |
|---|---|---|
| eyebrow | 위치 표시 | `실습 2 · 30분` |
| h1 | 페이지 이름 | `브랜드 마케팅 전략보고서` |
| 학습 목표 | **덮을 때 할 수 있게 되는 것 한 문장** | `독립 조사 → 통합 → 별도 검토를 프롬프트 한 편에 담을 수 있다` |

학습 목표 문장은 "~를 이해한다"로 쓰지 않는다. 이해했는지는 아무도 판정할 수 없다. "~를 만들 수 있다 / 구분할 수 있다 / 판정할 수 있다"로 쓴다.

## 용어사전 — 확정 표기

`_workspace/00_architect_glossary.md`에 아래 형식으로 확정하고, 모든 원고를 여기에 맞춘다. 같은 개념의 두 번째 이름이 등장하는 순간 비전공자는 새 개념이 나온 줄 안다.

| 용어 | 확정 표기 | 금지 표기 | 한 줄 풀이 (첫 등장 시 붙인다) |
|---|---|---|---|
| harness | 하네스 | 하니스, Harness(본문) | 업무 설명을 AI 팀 구조로 바꿔 주는 도구 |
| agent | 에이전트 | 요원, 상담원, 에이전시 | 특정 역할을 맡은 AI 담당자 — **누가** |
| skill | 스킬 | 기능, 능력, 역량 | 그 담당자가 따르는 절차와 기준 — **어떻게** |
| orchestrator | 오케스트레이터 | 지휘자, 조율자, 총괄기 | 누가 언제 어떤 순서로 일하는지 정해 둔 것 |
| agent team | 에이전트 팀 | 멀티에이전트, 팀에이전트 | 서로 대화하며 일하는 에이전트 묶음 |
| brief | 브리프 | 지시문, 요청문, 프롬프트(혼용 금지) | 하네스에 주는 업무 설명 한 편 |

패턴 6종의 표기는 `harness-concept-source` 스킬이 원본에서 확정하며, 정보설계는 그것을 그대로 받아 쓴다. 두 스킬이 각자 이름을 정하면 개념 페이지와 실습 페이지가 갈라진다.

## 톤 규칙

- **경어체 평서형** (`~합니다`). 명령형(`~하라`)은 실습 절차의 단계 문장에만 쓴다.
- **한 문장 60자 이내를 기본.** 두 개의 주장이 한 문장에 있으면 자른다.
- **굵게는 페이지당 15회 이내.** 다 강조하면 아무것도 강조되지 않는다.
- **전문용어는 첫 등장에 괄호 풀이 한 줄.** 두 번째부터는 붙이지 않는다.
- **비유는 한 페이지에 하나.** 비유가 겹치면 학습자는 비유끼리 연결하려 애쓴다.

## 분량 관리 — 시간으로 환산해 검증한다

학습 시간 1분 ≈ 한국어 본문 250자(도식·표는 제외). 상한을 넘으면 줄인다.

| 페이지 | 목표 시간 | 본문 상한 |
|---|---|---|
| 홈 | 3분 | 800자 |
| 개념 | 15분 | 4,000자 |
| 실습 1 | 25분 (읽기 8분 + 실행 17분) | 2,000자 |
| 실습 2 | 30분 (읽기 10분 + 실행 20분) | 2,500자 |
| 실습 3 | 40분 (읽기 12분 + 실행 28분) | 3,000자 |

실습 페이지의 상한이 개념보다 낮은 것은 의도적이다. 실습 시간의 대부분은 **읽는 시간이 아니라 AI를 돌리고 결과를 보는 시간**이어야 한다. 실습 페이지가 길어지면 학습자는 실행 대신 독서를 한다.

줄이는 순서: ① 배경 설명 삭제 → ② 산문을 표로 → ③ 예시 개수 축소 → ④ 섹션 통합. **검토 체크리스트·프롬프트 원문·준비물 블록은 마지막까지 줄이지 않는다** — 이 셋이 실습의 실행 가능성을 만든다. 준비물을 줄이면 페이지는 짧아지고 실습은 시작되지 않는다.

## 봉합 체크 (최종 편집)

모든 원고가 모인 뒤 이 순서로 점검하고, 항목별로 수정 지시를 작성자에게 보낸다.

1. 5개 페이지의 학습 목표 문장을 나란히 읽는다 — 중복되거나 비는 구간이 있는가
2. 실습 3장의 8블록 골격이 동일한가 (블록 순서·이름)
3. 패턴 이름이 개념 페이지와 실습 페이지에서 동일한가
4. 용어사전 금지 표기가 남아 있는가 (grep으로)
5. 각 페이지 분량이 상한 안인가
6. 페이저(이전/다음)가 끊기는 페이지가 있는가
7. 개념 페이지가 실습 페이지 합계보다 길지 않은가 — 길면 설계 실패, 개념을 줄인다
