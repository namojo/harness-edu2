## 2. 인용 시 확인할 것

- **패턴 개수와 이름** — 원본이 패턴을 추가/개명했는지. 교재는 6개를 가르치므로, 추가된 패턴이 6개 중 하나를 대체해야 하는지 판단이 필요하다.
- **메타스킬 단계 수** — 원본 SKILL.md의 Phase 번호가 바뀌었는지. 교재는 Phase 1~6을 6단계로 가르친다.
- **진화 메커니즘 명칭** — 원본이 이 용어를 유지하는지. 교재의 1부 3번 블록 전체가 이 개념에 의존한다.
- **트리거 문구** — `"하네스 구성해줘"`. 실습 1의 브리프 첫 줄이 이 문구다. 원본이 트리거를 바꾸면 실습 3장이 전부 영향을 받는다.
- **설치 명령** — `/plugin marketplace add revfactory/harness`, `/plugin install harness@harness-marketplace`. 설치가이드와 홈 페이지에 함께 등장한다.

## 3. 교재가 의도적으로 원본과 다르게 한 것

이 목록은 QA가 "불일치"로 잡지 않도록 하기 위해 존재한다. 여기 없는 불일치는 결함이다.

| 항목 | 원본 | 교재 | 사유 |
|---|---|---|---|
| 패턴 개수 | 8개 | 6개 + 각주 2개 | 15분 안에 8개는 남지 않는다 |
| 메타스킬 단계 | Phase 0~7 (8단계) | 6단계 (Phase 1~6) + 각주 | 첫 구성 경험에 보이는 것이 6단계 |
| 실행 모드 | 3종 (팀 / 서브 / 단계별 재구성) | 2종 (팀 / 서브) + 각주 | 단계별 재구성은 15+ 에이전트 규모의 이야기 |

각 항목은 교재 본문에 각주로 명시한다. 축약을 숨기면 원본을 본 학습자가 교재를 틀렸다고 판단한다.

## 4. 원본 갱신 감지

개념 페이지를 손볼 때마다 다음을 실행해 원본이 바뀌었는지 확인한다.

```bash
# 패턴 표가 여전히 8행인지, 이름이 그대로인지
grep -n -A 14 "### 아키텍처 패턴" /Users/andy/Work/harness/README_KO.md

# 메타스킬 Phase 목록
grep -n "^### Phase" /Users/andy/Work/harness/skills/harness/SKILL.md

# 트리거 문구와 설치 명령
grep -rn "하네스 구성해줘\|plugin marketplace add\|plugin install harness" /Users/andy/Work/harness/README_KO.md
```

바뀐 것이 있으면 위 §2·§3 표를 먼저 갱신하고, 그 다음 `_workspace/02_curator_sources.md`에서 영향받는 문장을 찾아 고친다. 본문을 먼저 고치면 대조표가 낡는다.
