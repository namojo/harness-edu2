# 브리프 원문 정본 — 3편

이 파일이 브리프 프롬프트의 **유일한 정본**이다. 웹페이지·슬라이드·강사 자료가 갈릴 때 이 파일을 기준으로 맞춘다.
집필 시 **여기서 복사**하고, 완성 후 diff로 검증한다. 눈으로 읽어서 "같다"고 판정하지 않는다 — 복사해서 붙여넣는 것이 실습의 첫 동작이므로, 보이지 않는 문자 하나가 실습을 막는다.

## 실습 1 · 유튜브 콘텐츠 기획 팀

**출처:** 사용자 확정 원문 (워크샵 pptx 슬라이드 11과 동일)

```
하네스를 구성해줘.
[브랜드/주제]를 위한 유튜브 콘텐츠 기획 팀이 필요해.
트렌드 조사, 8–10분 대본 기획, 제목·태그 SEO, 썸네일 콘셉트를 맡기고,
최종적으로 1주치 콘텐츠 기획안을 만들어줘.
대상은 [20대 직장인]이고, 주장마다 근거 출처를 남겨줘.
```

- 5행, 플레이스홀더 2개: `[브랜드/주제]`, `[20대 직장인]`
- **함정:** 3행 `8–10분`의 대시는 하이픈(`-`)이 아니라 **en dash(`–`, U+2013)** 다.

**브리프 4요소 해설용 매핑**

| 요소 | 값 | 원문 근거 |
|---|---|---|
| 목표 | 1주치 콘텐츠 기획안 | 4행 |
| 대상 | 20대 직장인 | 5행 |
| 역할 | 트렌드 조사 · 대본 기획 · 제목·태그 SEO · 썸네일 콘셉트 | 3행 |
| 기준 | 주장마다 근거 출처 | 5행 |

## 실습 2 · 브랜드 마케팅 전략보고서

**출처:** 사용자 확정 원문 (워크샵 pptx 슬라이드 16과 동일)

```
[브랜드]의 [제품/서비스]를 위한  마케팅 전략보고서 하네스를 구성해줘.
시장·고객·경쟁·채널을 독립적으로 조사한 뒤 전략가가 통합하고,
별도 리뷰어가 근거·실행 가능성·누락을 점검하게 해줘.
최종 산출물은 1페이지 요약, 실행 우선순위 표, 측정지표를 포함해줘.
사실과 가정을 구분하고 모든 외부 주장에 출처를 남겨줘.
```

- 5행, 플레이스홀더 2개: `[브랜드]`, `[제품/서비스]`
- **함정:** 1행 `위한  마케팅` 사이에 **공백이 2개** 있다. 원문 그대로 보존한다.

이 브리프는 패턴 두 개를 프롬프트 안에 명시하고 있다는 점을 해설에서 짚는다:
- `시장·고객·경쟁·채널을 독립적으로 조사한 뒤 전략가가 통합` → **팬아웃 / 팬인**
- `별도 리뷰어가 근거·실행 가능성·누락을 점검` → **생성-검증**

**브리프 4요소 해설용 매핑**

| 요소 | 값 | 원문 근거 |
|---|---|---|
| 목표 | 1페이지 요약 + 실행 우선순위 표 + 측정지표 | 4행 |
| 대상 | (브랜드의 제품/서비스 담당) — 학습자가 채운다 | 1행 |
| 역할 | 시장·고객·경쟁·채널 조사자 4 + 전략가 1 + 리뷰어 1 | 2~3행 |
| 기준 | 사실/가정 구분, 모든 외부 주장에 출처 | 5행 |

## 실습 3 · 샘플 형식으로 새 PPT 만들기

**출처:** 사용자 지시 기반 확정안. 워크샵 pptx 슬라이드 20의 원문을 **하네스 구성 브리프 형태로 확장**한 것이다 (사용자 지시: *"…똑같이 수준 높은 퀄리티의 pptx를 만들도록 하는 하네스를 구성하는 식으로 작성"*).

```
sample.pptx의 형식과 디자인을 재해석해 전략 보고서를 PPT로 만드는 하네스를 구성해줘.
먼저 sample.pptx에서 형식 규칙 — 폰트 계층, 외곽 여백, 정렬선, 색의 역할, 카드·표현 방식, 한 장의 정보량 — 을 추출하게 해줘.
그 규칙과 실습 2에서 만든 마케팅 전략보고서를 이용해 새 슬라이드 3장을 만들어줘.
1장은 문제와 기회, 2장은 실행 우선순위, 3장은 측정과 다음 행동으로 구성해줘.
내용 리뷰와 형식 리뷰를 맡는 리뷰어를 각각 두고, 텍스트·표·도형은 편집 가능하게 유지해줘.
```

- 5행, 플레이스홀더 없음 (실습 2 산출물과 `sample.pptx`가 입력)

### pptx 원문과의 차이 — 의도된 것이므로 QA가 불일치로 잡지 않는다

| pptx 슬라이드 20 원문 | 확정안 | 사유 |
|---|---|---|
| `첨부한 샘플 PPT 1장의 형식 규칙을 분석해줘.` | `sample.pptx의 형식과 디자인을 재해석해 … 하네스를 구성해줘.` | 실습 1·2와 동일하게 **하네스 구성 브리프**로 통일. 실습 3만 단발 요청이면 세 실습의 성장 서사가 끊긴다 |
| `내용 리뷰와 형식 리뷰를 분리하고` | `내용 리뷰와 형식 리뷰를 맡는 리뷰어를 각각 두고` | 리뷰를 "행위"가 아니라 **역할**로 요청해야 팀이 만들어진다 |
| `첨부한 샘플 PPT 1장` | `sample.pptx` | 파일명을 고정해 학습자가 무엇을 첨부해야 하는지 모호하지 않게 |

### 추출할 형식 규칙 6종 (변경 금지)

"예쁘게 따라 해" 대신 **추출할 항목을 명시하는 것**이 이 실습의 핵심 교육 포인트다. 6종을 줄이거나 늘리지 않는다.

1. 폰트 계층 (제목/소제목/본문/캡션의 크기·굵기 관계)
2. 외곽 여백 (슬라이드 가장자리 안전 영역)
3. 정렬선 (좌측 기준선, 열 구조)
4. 색의 역할 (지배색 / 강조색 / 상태색의 쓰임 구분)
5. 카드·표현 방식 (정보를 담는 반복 단위)
6. 한 장의 정보량 (한 슬라이드가 다루는 메시지 개수)

### 3장의 스토리 구조 (변경 금지)

`문제 → 선택 → 측정`

| 장 | 제목 | 답해야 하는 질문 |
|---|---|---|
| 1 | 문제와 기회 | 왜 지금 이 타깃과 메시지인가? |
| 2 | 실행 우선순위 | 무엇을 먼저, 누가, 언제 할 것인가? |
| 3 | 측정과 다음 행동 | 무엇으로 성공을 판단할 것인가? |

세 장 모두 **편집 가능**해야 한다 — 텍스트는 텍스트 프레임, 표는 표, 도형은 도형. 이미지로 굽힌 슬라이드는 실패다. 학습자가 실무에 쓸 수 없기 때문이다.

### 시간 배분 (pptx 슬라이드 20 정본)

`팀 실행 15분 · 스토리 확인 5분 · 수정 15분 · 공유 5분` = 40분

## 보존 함정 — 반드시 읽을 것

집필·구현 과정에서 아래가 조용히 바뀐다. 전부 실습을 실제로 망가뜨린다.

| # | 함정 | 어디서 깨지나 | 확인 |
|---|---|---|---|
| 1 | **en dash → 하이픈** (`8–10분` → `8-10분`) | 에디터 자동 교정, 손으로 다시 타이핑 | `grep -c '8–10분'` |
| 2 | **이중 공백 → 단일 공백** (`위한  마케팅`) | HTML은 연속 공백을 하나로 렌더한다. `<pre>` 밖에 넣으면 사라진다 | 브리프는 반드시 `<pre>` 안에 |
| 3 | **가운뎃점(·) → 쉼표나 슬래시** | "읽기 좋게" 다듬는 충동 | `grep -o '·' \| wc -l` 로 개수 대조 |
| 4 | **플레이스홀더에 태그가 섞임** | 강조 스타일을 `<span>`으로 넣으면 클립보드에 태그가 들어간다 | 복사 버튼을 실제로 눌러 붙여넣어 확인 |
| 5 | **줄바꿈 유실** | `<pre>` 대신 `<p>`를 쓰면 5행이 1행이 된다 | 붙여넣은 결과의 행 수가 5인지 |
| 6 | **줄 끝 공백 추가** | 자동 포매터 | `grep -n ' $'` |
| 7 | **전각 괄호 `［］`** | 한글 입력기 상태 | `grep -o '\[' \| wc -l` |

**2번이 가장 자주 깨지고 가장 눈에 안 띈다.** 브리프 프롬프트를 `<pre>` 밖에 두지 않는다.

## 검증 방법

브리프 원문을 별도 텍스트 파일로 떼어 둔 뒤, 완성된 HTML에서 추출한 텍스트와 diff를 뜬다.

```bash
# 1) 정본을 파일로 (이 문서의 코드블록에서 복사)
#    _workspace/briefs/practice-1.txt 등으로 저장

# 2) HTML의 프롬프트 <pre>에서 텍스트 추출 후 비교
python3 - <<'PY'
import html, re, pathlib, sys, difflib
page = pathlib.Path('docs/practice/1-youtube.html').read_text(encoding='utf-8')
m = re.search(r'<pre[^>]*class="[^"]*brief[^"]*"[^>]*>(.*?)</pre>', page, re.S)
if not m:
    sys.exit('브리프 <pre class="...brief...">를 찾지 못했습니다')
got = html.unescape(re.sub(r'<[^>]+>', '', m.group(1))).strip('\n')
want = pathlib.Path('_workspace/briefs/practice-1.txt').read_text(encoding='utf-8').strip('\n')
if got == want:
    print('일치 ✓')
else:
    print('불일치:')
    for line in difflib.unified_diff(want.splitlines(), got.splitlines(),
                                    '정본', 'HTML', lineterm=''):
        print(' ', line)
PY
```

diff가 비어야 통과다. **문자 단위 비교 없이 통과 처리하지 않는다** — 위 함정 1·2·3은 눈으로는 절대 잡히지 않는다.
