## 실습 1 · 유튜브 콘텐츠 기획 팀

**학습 목표 (블록 1):** 업무 설명 한 문장으로 전문가 팀이 만들어지는 것을 직접 볼 수 있다.

**가르치는 것:** 패턴 이름이 아니라 **팀 구성 자체**. 역할 경계와 전달 관계가 어떻게 정해지는가.

### 블록 2 · 준비물

입력 파일 없음. 브리프 한 편이 전부다.

> **준비물:** 입력 파일이 없습니다. Claude Code가 실행되고 하네스 플러그인이 설치되어 있으면 됩니다.
> 확인이 필요하면 [설치가이드](../install/index.html)로 가세요.
> 실습 저장소를 받아 두었다면 `harness-edu/workshop/practice-1-youtube/README.md` 에 같은 브리프가 있습니다.

### 블록 3 · 이번 실습에서 확인할 것 (3개)

1. **INPUT** — 업무 설명 한 문장이 입력이다
2. **TEAM** — 하네스가 역할을 나누고 전달 관계를 정한다
3. **OUTPUT** — 네 담당의 결과가 하나의 기획안으로 묶인다

### 블록 5 · 예상 팀 (기준선)

| 역할 | 책임 | 전달물 |
|---|---|---|
| 트렌드 리서처 | 20대 직장인 관심 소재 조사, 출처 확보 | 소재 후보 + 근거 링크 |
| 대본 기획자 | 8–10분 분량 구조 설계 | 구성안 (도입·전개·마무리) |
| SEO 담당 | 제목·태그 후보 작성 | 제목 3안 + 태그 세트 |
| 썸네일 콘셉트 | 시각 후크 설계 | 콘셉트 문구 + 구도 설명 |
| **편집 통합** | 네 담당의 결과를 **하나의 기획안으로** 묶기 | 1주치 콘텐츠 기획안 |

**표 위에 반드시 둘 문장:** "팀은 실행할 때마다 달라집니다. 아래는 정답이 아니라 대조용 기준선입니다."

### 블록 6 · 예상 산출물

**1주치 콘텐츠 기획안 한 편.**

**브리프는 편수를 정하지 않았다.** 몇 편이 나오는지는 하네스가 정하며, 개수는 판정 기준이 아니다. `5편`·`요일별` 같은 숫자를 원고에 만들어 넣지 마라 — 브리프에 없는 것을 기준으로 제시하면 학습자가 자기 결과를 틀렸다고 판단한다.

품질 기준은 **네 담당의 결과가 서로 연결되어 있는가**다. 트렌드 리서처가 고른 소재에 대해 대본 구성이 있고, 그 소재에 맞는 제목·태그와 썸네일 콘셉트가 붙어 있어야 한다. 조사·대본·제목·썸네일이 **네 덩어리로 나열되어 있으면 통합이 안 된 것**이며, 그것이 이 실습에서 확인할 전달 관계의 실물이다.

### 블록 7 · 검토 체크리스트 (6개 중 5개 이상 통과)

- [ ] 에이전트가 4개 이상 만들어졌고, 두 에이전트의 책임이 겹치는 곳이 없다
- [ ] 누가 누구에게 무엇을 넘기는지가 명시되어 있다
- [ ] 최종 산출물의 형식(1주치 기획안)이 정해져 있다
- [ ] 대상(20대 직장인)에게 왜 이 소재인지가 적혀 있다
- [ ] 외부 사실 주장마다 출처가 붙어 있다 (붙지 않은 문장을 세어 보세요)
- [ ] 네 담당의 결과가 서로 연결되어 있다 — 조사한 소재에 대본·제목·썸네일이 각각 붙어 있다

### 블록 8 · 이럴 때는 (실습 1 고유)

| 증상 | 대응 |
|---|---|
| 하네스가 트리거되지 않고 기획안만 바로 나온다 | 브리프 첫 줄 `하네스를 구성해줘.`가 있는지 확인. 플러그인 설치는 설치가이드 참조 |
| 팀이 8명 넘게 만들어진다 | 역할을 묶어 다시 요청 — "조사와 SEO를 한 사람이 맡아도 됩니다" |
| 출처가 하나도 없다 | 하네스가 웹 조사를 하지 않았을 수 있다. "실제 검색으로 근거를 확인해 달라"를 추가해 재실행 |
| 브랜드를 안 정해서 막힌다 | 아무 공개 브랜드나 관심 주제로 넣는다. 실제 업무 데이터는 넣지 않는다 |

**데이터 안전 원칙을 이 페이지에 한 번 명시한다.** (실습 2·3은 여기로 링크)

### 블록 9 · 다음 단계

## 실습 2 · 브랜드 마케팅 전략보고서

**학습 목표:** 독립 조사 → 통합 → 별도 검토를 프롬프트 한 편에 담을 수 있다.

**가르치는 것:** **팬아웃 / 팬인** + **생성-검증**. 두 패턴이 한 브리프에 겹쳐 들어간다는 것을 보여주는 것이 핵심이다.

### 블록 2 · 준비물

입력 파일 없음. 단, **결과를 저장할 곳**을 미리 정한다 — 실습 3이 이 산출물을 입력으로 쓴다.

> **준비물:** 입력 파일이 없습니다. 다만 이 실습의 결과물을 실습 3에서 다시 쓰므로,
> 작업 폴더를 정해 두고 결과를 파일로 저장하세요 (예: `_workspace/strategy.md`).

### 블록 3 · 이번 실습에서 확인할 것 (3개)

1. **PATTERN** — 관점은 병렬로, 결론은 하나로
2. **REVIEW** — 만든 사람이 아닌 눈이 검사한다
3. **EVIDENCE** — 사실과 가정이 구분되어 표기된다

### 블록 5 · 예상 팀 (기준선)

```
        ┌─ 시장 조사 (카테고리·변화) ─┐
브리프 ─┼─ 고객 조사 (니즈·장벽) ────┼─→ 전략가 (통합) ─→ 리뷰어 (검증) ─→ 최종
        ├─ 경쟁 조사 (포지션·격차) ──┤
        └─ 채널 조사 (도달·비용) ────┘
           ↑ 팬아웃 / 팬인              ↑ 생성-검증
```

| 역할 | 책임 | 전달물 |
|---|---|---|
| 시장 조사자 | 카테고리 규모·변화 | 사실 + 출처 |
| 고객 조사자 | 니즈·구매 장벽 | 사실 + 출처 |
| 경쟁 조사자 | 경쟁 포지션·격차 | 사실 + 출처 |
| 채널 조사자 | 채널별 도달·비용 | 사실 + 출처 |
| 전략가 | 4개 조사를 하나의 선택으로 통합 | 1페이지 요약 + 우선순위 표 + 측정지표 |
| 리뷰어 | 근거·실행 가능성·누락 점검 | 검토 의견 + 수정 요청 |

**조사자 4명이 서로를 기다리지 않는다는 점**을 도식으로 보여준다. 이것이 팬아웃/팬인의 실물이다.

### 블록 6 · 예상 산출물

`관찰(사실·출처) → 해석(가정) → 선택(전략) → 측정(지표)` 4층 구조.

**좋은 전략보고서는 정보보다 선택을 보여준다.** 그래서 1페이지 요약에 **"무엇을 하지 않을 것인가"** 가 있어야 한다. 이 문장을 페이지에 반드시 남긴다 — 학습자가 자기 결과를 판정하는 가장 강력한 기준이다.

### 블록 7 · 검토 체크리스트 (7개 중 6개 이상 통과)

- [ ] 조사 담당이 4개 관점으로 나뉘어 있고, 서로의 결과를 기다리지 않는 구조다
- [ ] 통합을 담당하는 역할과 검증을 담당하는 역할이 **다른 에이전트**다
- [ ] 1페이지 요약이 실제로 1페이지 분량이다
- [ ] 1페이지 요약에 "무엇을 하지 않을 것인가"가 적혀 있다
- [ ] 실행 우선순위 표에 판단 근거 열이 있다
- [ ] 사실과 가정이 표기로 구분되어 있다 (예: `[사실]` / `[가정]`)
- [ ] 모든 외부 주장에 출처가 붙어 있다

### 블록 8 · 이럴 때는 (실습 2 고유)

| 증상 | 대응 |
|---|---|
| 리뷰어가 "문제 없음"만 말한다 | 리뷰 기준을 브리프에 구체화 — "근거 없는 주장, 실행 주체 없는 항목, 누락된 관점 3가지를 지적해 달라" |
| 4개 조사 결과가 서로 베낀 것처럼 같다 | 조사자별 질문을 다르게 지정해 재실행 |
| 사실/가정 구분이 없다 | 5행 기준 문장을 강조해 재실행. 하네스가 스킬에 표기 규칙을 안 넣은 것 |
| 시간이 부족하다 | 조사 항목 개수 상한(관점별 3개)을 브리프에 추가 |
| 출력이 너무 길다 | "1페이지 요약"의 분량을 글자 수로 지정 |

### 블록 9 · 다음 단계

**실습 3이 이 산출물을 입력으로 쓴다.** 결과를 파일로 저장해 두라고 명시한다 (예: `_workspace/` 또는 사용자 폴더). 저장하라는 안내가 없으면 실습 3에서 다시 만들어야 한다.

## 실습 3 · 샘플 형식으로 새 PPT 만들기

**학습 목표:** 앞 실습의 산출물을 다음 실습의 입력으로 재사용하고, 내용과 형식을 분리해 검토할 수 있다.

**가르치는 것:** **파이프라인** + 형식/내용 **검토 분리**.

### 블록 2 · 준비물 — 이 실습에서 가장 중요한 블록

파일 두 개가 필요하고, 그중 하나는 앞 실습의 산출물이다. **우회 경로 없이 의존성만 쓰면 교실 절반이 여기서 멈춘다.**

| 필요한 것 | A. 실습 저장소를 받은 경우 | B. 개별 다운로드 |
|---|---|---|
| `sample.pptx` — 형식·디자인 참조 원본 | `harness-edu/workshop/practice-3-pptx/sample.pptx` | 다운로드 링크 (용량 표기) |
| 전략보고서 — 슬라이드에 담을 내용 | 실습 2의 결과물 | 실습 2를 건너뛴 경우 `example-strategy.md` |

> **이 실습은 실습 2의 결과물을 씁니다.** 실습 2를 마쳤다면 그 전략보고서를 준비하세요.
> 건너뛰었다면 `example-strategy.md` 를 내려받아 대신 쓰면 됩니다 — 실습 3만 따로 해도 됩니다.

다운로드 URL과 용량은 `_workspace/07_assets_manifest.md`에서 가져온다. 페이지에서 URL을 조립하지 않는다.

### 블록 3 · 이번 실습에서 확인할 것 (5개 — pptx 정본)

1. **REFERENCE** — 샘플 PPT 1장
2. **CONTENT** — 실습 2 전략
3. **SCOPE** — 새 3장
4. **FORMAT** — 편집 가능
5. **REVIEW** — 내용 + 형식

### 블록 5 · 예상 팀 (기준선)

```
sample.pptx ─→ 형식 분석가 ─┐
                            ├─→ 슬라이드 제작자 ─┬─→ 내용 리뷰어 ─┐
실습 2 전략 ─→ 내용 구성자 ─┘                     └─→ 형식 리뷰어 ─┴─→ 최종
                    ↑ 파이프라인                        ↑ 검토 분리
```

| 역할 | 책임 | 전달물 |
|---|---|---|
| 형식 분석가 | sample.pptx에서 규칙 6종 추출 | 형식 규칙 명세 |
| 내용 구성자 | 전략보고서를 3장 스토리로 재구성 | 장별 메시지·데이터 |
| 슬라이드 제작자 | 규칙 + 내용으로 pptx 생성 | 편집 가능한 3장 |
| 내용 리뷰어 | 메시지·근거·수치 점검 | 내용 수정 요청 |
| 형식 리뷰어 | 규칙 준수·오버플로·정렬 점검 | 형식 수정 요청 |

### 블록 6 · 예상 산출물

3장짜리 의사결정 스토리: `문제와 기회` → `실행 우선순위` → `측정과 다음 행동`. 세 장 모두 **EDITABLE**.

### 블록 7 · 검토 체크리스트 — 두 열을 모두 통과해야 통과다

**이 실습의 체크리스트는 2열로 나눈다.** 내용과 형식을 따로 검토하는 것 자체가 학습 내용이다.

| 내용 검토 | 형식 검토 |
|---|---|
| 1장이 "왜 지금 이 타깃인가"에 답하는가 | 본문 폰트 크기가 3장에서 서로 같은가 |
| 2장에 실행 주체와 시점이 있는가 | 좌측 정렬선이 3장에서 어긋나지 않는가 |
| 3장의 지표가 측정 가능한 수치인가 | 텍스트가 도형 밖으로 넘치지 않는가 |
| 전략보고서에 없던 사실이 새로 등장하지 않았는가 | 색이 샘플의 역할 구분(지배/강조/상태)을 따르는가 |
| 세 장이 하나의 이야기로 읽히는가 | 텍스트·표·도형이 편집 가능한가 (클릭해서 커서가 들어가는가) |

마지막 형식 항목은 반드시 넣는다. **이미지로 굽힌 슬라이드는 실무에 쓸 수 없다.**

### 블록 8 · 이럴 때는 (실습 3 고유)

| 증상 | 대응 |
|---|---|
| 슬라이드가 이미지로 나와 편집이 안 된다 | "텍스트·표·도형은 편집 가능하게 유지" 문장을 다시 강조해 재실행 |
| 샘플과 전혀 다른 디자인이 나온다 | 형식 규칙 6종을 실제로 추출했는지 먼저 확인. 추출을 건너뛰고 바로 만들면 이렇게 된다 |
| 텍스트가 도형 밖으로 넘친다 | 한 장의 정보량 규칙 위반. "한 장에 메시지 1개"로 제한해 재실행 |
| 한글이 깨지거나 폰트가 바뀐다 | 시스템에 없는 폰트를 지정한 경우. 샘플에 쓰인 폰트명으로 고정 요청 |
| 실습 2 결과가 없다 | 예시 전략보고서 사용 (의존성 고지 참조) |
| 40분을 넘긴다 | 3장을 2장으로 줄인다. 완성 경험이 장 수보다 중요하다 |

### 블록 9 · 다음 단계

세 실습이 한 팀의 세 단계였음을 정리한다: **팀을 만든다 → 구조를 고른다 → 산출물을 다듬는다.** 그리고 학습자 자신의 업무로 브리프를 다시 써 보게 한다 (4요소 틀 재사용).

자산의 정의·제작·저장소 배치·다운로드 링크는 **`practice-assets` 스킬**이 담당한다. 이 문서는 "무엇이 왜 필요한가"만 정하고, "어떻게 확보하고 어디에 두는가"는 그쪽에서 정한다.

| `example-strategy.md` | 실습 3 블록 2 | 실습 2를 건너뛴 학습자의 입력 | 교실 절반이 멈춘다 |
